# Where the data lives

This repository holds **code and small inputs only**. The flux and meteorological
data are archived separately so they carry their own citable DOIs. This file
lists every input the analysis needs, where it comes from, and its licence.

Run `code/check_data.R` at any point to see which inputs are present and which
are still missing.

All three archives are published. The DOIs below are **concept DOIs** — they always
resolve to the newest version of each record.

---

## 1. Archived with this paper

| What | Where | Licence |
|---|---|---|
| **Aggregated processed products** — 52 files: the 48-point monthly diel composites, light-response parameter tables, daily/16-day/monthly carbon-balance and meteorology summaries, per-year coverage and energy-balance closure tables, the storage-term comparison, and the morning-transition, partitioning and VPD-constraint result tables | Zenodo [`10.5281/zenodo.22838676`](https://doi.org/10.5281/zenodo.22838676) | CC BY 4.0 |
| **Half-hourly record**, 2017-01-01 to 2024-10-15 — 24 columns of CO2, energy and meteorological series (136,559 half-hours) | Zenodo [`10.5281/zenodo.22839383`](https://doi.org/10.5281/zenodo.22839383) | CC BY 4.0 |
| **Analysis code** — this repository | Zenodo [`10.5281/zenodo.22838256`](https://doi.org/10.5281/zenodo.22838256) | MIT |
| **Curated long-term record** for site PE-TNR | [AmeriFlux PE-TNR](https://ameriflux.lbl.gov/sites/siteinfo/PE-TNR) | per AmeriFlux site policy |

To reproduce the figures, download the half-hourly record and place it at
`data/dataset_from_matlab.csv`.

The two released data products are built reproducibly from this repository:
`code/zz_build_zenodo_deposit.R` assembles the aggregated deposit, and
`code/zz_build_halfhourly_release.R` assembles the half-hourly record. Both
write to a gitignored directory ready for upload. The half-hourly builder
selects its 24 columns from an explicit allowlist and refuses to write anything
outside it, so the published column set cannot drift if the upstream export
changes.

## 2. Third-party inputs — obtain from the provider

These are **not redistributed here**.

### GPM IMERG precipitation

- **What:** `GPM_3IMERGHH` Version 07 Final, 30-minute, 0.1° × 0.1°
- **DOI:** [10.5067/GPM/IMERG/3B-HH/07](https://doi.org/10.5067/GPM/IMERG/3B-HH/07)
- **Source:** NASA GES DISC
- **Needed by:** `code/03`, `04`, `13`, `14` (Fig 1, Fig 3, Fig S2 and the precipitation context)
- **Place at:** `data/` — any filename matching `imerg.*30min.*\.csv` is picked up.
  The version used here covers the tower grid cell for 2017–2024, aggregated from
  the native half-hourly product.

### WorldClim 2.1

- **What:** 10 arc-minute mean monthly precipitation, 1970–2000
- **Source:** [worldclim.org](https://worldclim.org)
- **Needed by:** `code/13_maps.R` (the Figure 1 basemap)
- **Licence:** **redistribution is expressly forbidden** by WorldClim's own terms,
  which is why it is absent here.
- **Place at:** `data/worldclim/climate/wc2.1_10m/`. If the directory is missing,
  `code/13_maps.R` downloads it automatically via `geodata::worldclim_global()`.

### NOAA CPC Oceanic Niño Index

- **What:** ENSO phase classification from 3-month running mean SST anomalies in
  the Niño 3.4 region
- **Source:** [NOAA Climate Prediction Center](https://origin.cpc.ncep.noaa.gov/products/analysis_monitoring/ensostuff/ONI_v5.php)
- **Used for:** the ENSO phase labels applied throughout

### ERA5 boundary-layer height

- **Source:** Copernicus Climate Data Store
- **Used for:** the flux-footprint analysis (Fig S11), which was performed
  outside this repository

## 4. Generated by the pipeline — do not download

Everything else under `data/`, plus all of `figures/`, `output/` and `graphs/`,
is produced by the scripts. The chain starts from
`data/dataset_from_matlab.csv`:

```
data/dataset_from_matlab.csv          (download — section 1)
  └─ code/01  ─→ data/dataset_from_matlab_with_ENSO_season_NEEok_Reco_GEP.csv
       ├─ code/01b ─→ data/tambopata_48points_per_month_measured.csv   → Figs 4, 5, 6, S14–S16, S18
       ├─ code/02  ─→ data/enso_conditions_data.RData                  → code/03, code/13
       └─ code/04  ─→ data/tambopata_48points_per_month.csv, the 16-day tables,
                      Table 1, Table 3, Fig 2a, Fig 3
```

Note that `code/04` **rewrites** the enriched CSV in place to add the canopy
conductance columns, so `code/01` must run before `code/04`, and re-running
`code/01` strips those columns again. `scripts/run_all.ps1` encodes the correct
order.

## 5. Not reproducible from this repository

Stated plainly so nobody hunts for code that is not here:

| Figure | Why |
|---|---|
| **Fig S1** | site locator map, produced externally |
| **Figs S7, S8** | storage-term neural-network skill and permutation importance, trained externally |
| **Fig S11** | flux footprints, computed outside this repository using ERA5 boundary-layer height |

In addition, `code/23_canopy_temperature.R` needs the raw Biomet.net database for
its independent longwave validation. Without it the script still runs and still
writes `output/table_canopy_temperature.csv`, but **omits the Stefan-Boltzmann
validation rows** — so the table will be shorter than the published one. Set
`PETNR_DB_ROOT` if you have the database.
