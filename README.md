# tambopata-co2-gcb-2026

Analysis code for:

> Stern, R., Cruz, R., Negrón-Juárez, R., Ramos, E., Knox, S. H., Hoyt, A. M.,
> Jackson, R. B., Li, F., Dayalu, A., Pernak, R., Grace, J., Gloor, E.,
> Salinas, N., & Cosio, E. G. **Long-Term Flux Measurements in Southwestern
> Amazonia Reveal a Near-Neutral CO2 Balance and Unique Effects of El
> Niño-Southern Oscillation.** *Global Change Biology* (submitted).

Eddy-covariance CO2 and water fluxes at the Tambopata National Reserve, Madre de
Dios, Peru — AmeriFlux site **PE-TNR** (AndesFlux/PUCP), 12.8314° S, 69.2836° W.
Study period 2017-01-01 to 2024-10-15.

**This repository holds code and small inputs only.** The data are archived
separately with their own DOIs — see [DATA.md](DATA.md) for every input, its
source and its licence. [CONVENTIONS.md](CONVENTIONS.md) documents the
variable-naming contract, the sign conventions and the analytical rules.

---

## Quick start

R 4.5 or later. Scripts resolve every path through `code/paths.R`, which locates
the repository root by looking for `code/` and `data/` — so run them from
anywhere inside the clone.

**1. Get the data.** Download the half-hourly record (DATA.md §1) to
`data/dataset_from_matlab.csv`, and the IMERG precipitation CSV (DATA.md §2) to
`data/`.

**2. Check what is still missing:**

```powershell
.\scripts\run_check.ps1
```

**3. Run the full workflow:**

```powershell
.\scripts\run_all.ps1
```

On macOS or Linux, use the R equivalent:

```bash
Rscript scripts/run_all.R
```

Figures are written to `figures/`, tables and machine-readable results to
`output/`, diagnostics to `graphs/`. All three are gitignored — everything in
them is regenerated by the code.

To find which script produces a given figure, table or CSV:

```powershell
.\scripts\run_script.ps1 code\find_output.R Fig1
```

See [OUTPUT_INDEX.md](OUTPUT_INDEX.md) for more examples.

## Layout

| Path | Contents |
|---|---|
| `code/` | the analysis, numbered in run order; `paths.R`, `palette.R`, `ustar_filter.R` are shared helpers |
| `scripts/` | PowerShell and R runners |
| `data/` | small shipped inputs; everything else is downloaded or generated |

### Run order

`scripts/run_all.ps1` is the authority. Dependencies worth knowing:

1. `01_prepare_flux_timeseries.R` — builds the enriched half-hourly hub CSV
2. `01b_build_measured_composite.R` — the measured-only 48-point composite behind Figs 4, 5, 6 and S14–S16, S18
3. `02_resample_anova.R`, `03_meteorology_summary.R`
4. `07`, `08`, `17` — light-response parameter and residual panels, diagnostics
5. `04_diel_cycles_carbon_balance.R` — **rewrites the hub CSV in place**, adding canopy conductance; produces Fig 2a, Fig 3, Tables 1 and 3
6. `24_cumulative_diel_nee.R` — Figure 2 panel b; **must precede 15**
7. `14`, `15` — the environmental stack and the assembled Figure 2
8. `05`, `06`, `09`–`13`, `18` — light response, mixed models, driver bins, conductance, wind rose, maps
9. `19`–`22`, `25`–`27` — coverage and energy-balance closure (Tables S2, S3), storage comparison (Fig S10), half-hourly sensitivity (Table S7), morning transition, partitioning self-correlation, VPD-class light response (Fig 5)

`23_canopy_temperature.R` is run separately — see below.

### Building the released data products

Both Zenodo records are built from this repository, so the published data can be
regenerated and checked rather than taken on trust.

```powershell
.\scripts\run_script.ps1 code\zz_build_zenodo_deposit.R
```

Assembles the aggregated products into `data_release/` with a `MANIFEST.csv`, a
`data_dictionary.csv`, a README and a CC BY 4.0 licence.

```powershell
.\scripts\run_script.ps1 code\zz_build_halfhourly_release.R
```

Assembles the half-hourly record into `halfhourly_release/` — 136,559 half-hours
× 24 columns, truncated at 2024-10-15 to match Table S2. Columns come from an
explicit allowlist and the script aborts if the output contains anything else.

Both scripts rebuild their output tree from scratch on every run, and both
output directories are gitignored.

## Known limitations

**Four supplementary figures are not reproducible here.** Fig S1 (site locator),
Figs S7 and S8 (storage-term neural-network skill and permutation importance,
trained externally) and Fig S11 (flux footprints) were produced outside this
repository. See DATA.md §5.

**Figure 1 needs third-party rasters.** WorldClim's licence forbids
redistribution, so `code/13_maps.R` downloads it on first run.

**`code/23_canopy_temperature.R` degrades quietly without the raw database.** It
still writes `output/table_canopy_temperature.csv`, but omits the independent
Stefan-Boltzmann longwave validation rows, so the table is shorter than the
published one. Set `PETNR_DB_ROOT` to your copy of the Biomet.net database to get
the full table. `run_all.ps1` treats this script as optional and warns rather
than failing.

**The upstream MATLAB stage is not included.** `data/dataset_from_matlab.csv` is
produced by a Biomet.net pipeline that reads a raw instrument database not
distributed with this paper, so that step cannot be re-run from here. The
analysis begins from the archived half-hourly product. The three upstream
definitions that matter for interpreting it — PAR derived from shortwave as
`SW_IN × 2.3 − 1.22`, the storage term switching from modelled to
profile-measured in 2024, and `NEE = FC + SC` — are quoted verbatim in
[CONVENTIONS.md §0](CONVENTIONS.md).
